## 1. 產品與心智模型

**Apsis 是讓使用者透過聊天，帶領自己的 Bot 完成研發工作的地方。**

新使用者首次只預建一位 Bot；**不是 Bot 數量上限**。左側 Bots 的「＋」可隨時新增多位，可用角色模板或自行設定，各自保留主對話。既有多位 Bot、對話及收藏不因新預設而刪除或合併。一次完整交辦成為可追蹤任務，同一 Bot 可平行處理多個任務。專案連接既有本機 Repo，讓相關任務共用專案知識；每項開發任務有自己的工作分支與 worktree。

Workflow 透過 Skill 表達，不增加 Workflow 編輯器、節點画布或綁定設定。Plan 是單次任務可討論、可編輯的方案。Skill 可自動選用，也能明確指定，採用紀錄可查。

一般使用者主要看見：**Bot、任務、專案**。工作位置可查，但不要求使用者先理解 Workspace／Session／Context／Run 才能交辦。切任務頁籤切換的是正在看的工作，不能改變其他任務的工作目錄。

## 2. 資訊架構

| 區域         | 常駐內容                                                   | 按需展開                                                  |
| ------------ | ---------------------------------------------------------- | --------------------------------------------------------- |
| 左側導航     | Bots 分組及狀態 Tag、專案分組                              | 新增 Bot／專案，底部設定                                  |
| 主內容       | Bot 主對話、專案任務、任務工作頁                           | 已開任務頁籤，可關閉但不停止工作                          |
| 右側工作內容 | 預設不強迫常開，只有檔案／變更入口                         | 預覽／Diff，Git 紀錄在變更內展開；Plan 編輯時臨時打開文件 |
| 次級管理     | Bot 頭像／名稱開設定，Bot「⋯」開排程／背景，專案設定開知識 | 全域設定管理模型、模板、執行與語言；沒有 Skills 專頁      |

導航不能出現另一套「Workspace 管理」或「Workflow 管理」作為必經入口。Bots 與專案指向相同任務資料，不生成兩份紀錄。

## 3. 首次使用

初次畫面只有一位預設 Bot、模型連線引導與「加入本機專案」。模型設定成功即可聊天；涉及 Repo 的交辦才要求選定或加入專案。加入時顯示本機資料夾與辨識出的 Git 資訊，確認後保存為專案。不能悄悄另 clone 一份。

GitHub、GitLab、Azure DevOps 按 Repo remote 顯示相應連線入口；本機檢查不必等遠端 PR 認證全部完成。開 PR 前如缺認證，任務保留進度並在原處呈現可處理的問題。企業端點與認證細節尚需技術調查，不能假設全部是公有雲。

Bot 建立先顯示目前大頭貼、可自訂的 Bot 名稱、角色／模板與模型（可沿用預設）。點大頭貼可更換，進階指令、工具、權限放次級區域。**保留原有大頭貼、選擇與收藏系統，只移除動漫角色原名。** 使用者允許稍微簡化操作，而非拆除該系統。完整收藏細節另有入口，不用在建立 Bot 的表單中一次攤開；本提案不作素材授權結論或刪除收藏。

## 4. Bot 狀態與未讀回覆

直接進入 Bot 主對話，原型保留上次選擇的 Bot。移除全域工作總覽和待處理頁，透過每位 Bot 的狀態回答：**誰回覆了？誰需要我？誰仍在工作？**

- Bot 名稱下顯示「未讀回覆」「等你確認」「執行中」等精簡標籤，無待辦時顯示「可交辦」。原型側欄最多兩個標籤，對話標題可完整顯示並存狀態；具體聚合與優先順序是設計提案。
- 未讀與未處理分開。看到回覆後消除該項未讀，但計畫確認、問題、操作核准、知識建議及待 Review 成果，須實際處理後才消除待確認狀態。
- 原型以各任務最新回覆版本計算未讀，卡片實際進入可視範圍並短暫停留才標已讀；打開 Bot 不會一次清掉看不到的回覆。開啟任務只標記該任務已讀，不影響其他 Bot。
- Bot 主對話保留任務卡片；標題「任務」可查看該 Bot 的工作並直達任務。確認與成果回到相關對話／任務，不再建立另一個集中待處理頁。
- 瀏覽器／桌面通知僅用於 Q29 已確認的事件；點擊直達對應任務。普通階段進展留在產品內。
- 狀態用文字而非只有顏色表達；錯誤、離線、等待確認不能偽裝為執行中。

## 5. Bot 主對話：交辦與彙報

上方顯示 Bot 名稱、角色摘要、進行中任務數。訊息區保持可讀行寬，用自然回報與任務卡片串起歷史。卡片顯示目標、專案、狀態及下一步，點擊開任務頁籤。

輸入區由上到下：

1. 訊息內容與附件／引用。
2. 精簡控制：專案、起始分支、一般／Plan。Skills 直接在輸入框輸入 `/` 開啟清單，繼續輸入可篩選；不另設 Skills 按鈕或設定頁。未指定時保留 Bot 自動選用能力。
3. 送出。純聊天不要求選專案；意圖不明時就地確認新交辦或延續哪項任務。

交辦後**留在 Bot 主對話**，插入任務卡片，可再交辦其他需求。只有點卡片才切入任務工作頁。對話中的 task card 是資料視圖，不把整段主對話注入每個任務 context。

有未提交修改且意圖不明時，輸入區附近出現「接續目前修改／從最後提交開始」選擇。保留輸入草稿；不自動 stash、提交、刪除或移動原檔。沒有修改或指示明確時不重問。

## 6. 任務工作頁

頂部為可關閉頁籤；標題區顯示任務名稱、負責 Bot、專案、任務工作分支與狀態。左／中央保持任務對話，右側按需打開工具。

主區依序為任務摘要、可展開進度、對話與補充輸入。只顯示真實步驟與證據，不推算虛構完成百分比。完整工具／命令輸出可展開查阅。

補充訊息先顯示待採用，到可安全接續點後更新為已採用；停止是獨立控制。停止或頁籤關閉不會刪除工作。重啟後應重新查驗程序、Git 與外部任務狀態，不能僅靠舊模型文字假裝繼續成功。

父任務可展開分工與子任務；只有一位 Bot 時也能完成簡單流程。Skill 要求其他角色但尚未配置時，需要可理解的指派／建立入口，不能暗中創建整個團隊。這是待驗證的邊界，不在本原型中假裝已有協作執行器。

## 7. 變更、檔案與 Git

**變更面板**：列本任務相對基準的所有修改，顯示檔案數、增刪行與基準；桌面左右 Diff，窄畫面行內 Diff。可以選行引用到訊息，要求 Bot 修改；不加入通用程式碼編輯器。跨多則 Review 意見的草稿／批次送出可後續細化。

**檔案面板**：檔案樹與 Git 狀態，點檔案閱讀；Markdown 可渲染、文字程式碼唯讀，保留下載和引用。已發布成果仍是獨立快照。完整檔案 CRUD 不因原型重新加入。

**變更內的 Git 紀錄**：任務分支、起始分支、commit 關係、PR 目標可查。任務分支入口可暫停後切換，先檢查未提交內容與既有 PR，顯示實際將修改的目錄。不能將選新任務起點和切現有任務分支混用；不能暗中切原始 Repo。分支衝突處理及 worktree 清理須另有技術規格。

PR 正式核准／合併回原 Git 平台。PR 開啟時機、是否請 Reviewer 由任務指示／Skill 決定，界面展示實際狀態。後續 CI／Review 繼續進同一任務。任務最終完成與封存的精確判定仍需確認，不把「已開 PR」等同全部完成。

## 8. Plan 與驗證

Plan mode 產生本任務的可編輯計畫文件；對話用來釐清、修訂文件。顯示目前版本及待確認狀態，「開始實作」採用該版本，在同一任務繼續。檔案儲存、版本衝突、執行中變更計畫的確切邊界需要工程設計。原型中的編輯僅為記憶體示範。

參考的是先規劃、討論修訂再進入實作的互動：[Codex 指令](https://learn.chatgpt.com/docs/developer-commands)、[Codex prompting](https://learn.chatgpt.com/docs/prompting)、[Kimi Code 互動指南](https://moonshotai.github.io/kimi-code/en/guides/interaction.html)、[Kimi Code 工具規則](https://moonshotai.github.io/kimi-code/en/reference/tools.html)。本輪查核沒有足夠證據證明兩者都提供同樣的可直接編輯計畫 UI；獨立編輯文件及採用特定版本，是 Apsis 已確認需求的設計。

現有 Apsis 有 todo middleware 與 checkpoint，但尚非上述 Plan mode。現有 Skills 已有 `/` 搜尋選用、工具選單入口，以及本機與 `~/.agents/skills` 来源；應延伸既有能力，不另造流程管理系統。

網站驗證透過工具操作**外部使用者瀏覽器**。任務內提供開啟瀏覽器、驗證步驟、截圖／結果與操作紀錄，沒有嵌入式瀏覽器。連線失敗要顯示設定／重試，不把截圖當即時頁面。手機不暗示能直接操控手機瀏覽器或連上關機的桌機；遠端連線與授權方案仍待設計。

## 9. 設定與定期工作

- 模型／連接器：常用設定先顯示，技術參數折疊；連線結果與錯誤就地回饋。
- Skills：使用者明確要求只有輸入 `/` 顯示清單，不需要獨立設定頁。本提案移除 Skills 專頁、啟用清單、建立 Skill 表單與輸入区獨立 Skills 按鈕。原型支援文字篩選、上下鍵／Enter 或點選、Esc 關閉；選取只插入該則訊息，未送出前不執行，送出後不沿用成其他任務的隱藏設定。這不取消既有 Skill 檔案或 Bot 自動選用能力，也不代表移除模型／工具連線設定。
- 排程：選專案、固定分支、交辦文字／Skill、時間；顯示下次執行與紀錄。主機恢復後合併補跑一次，已有相同修復工作時須去重。排程執行上限沿用明確政策。
- 專案知識：既有規則可讀，Bot 建議新增內容需確認後生效；任務摘要自動保存。呈現來源、範圍與修改紀錄。
- 執行限制：時間／費用／嘗試上限可調整，無進展或超限需回報。Skill 不繞過一般授權。
- 個人化：主題、Bot 外觀、收藏等放設定；保留既有大頭貼、選擇與收藏能力，以及 Bot 自訂名字。頭像選擇以圖片、選取狀態及中性編號呈現，移除動漫角色原名。簡化的是入口與資訊密度，不是刪除既有功能或資料。

## 10. 視覺與響應式提案

延續既有低彩度底色與 Apsis 紫色，採清楚的層級與細分隔線。依 Q48 B+C，主對話放大原有頭像、加強名字與訊息區辨識；工作頁減少標題與區塊留白，右欄突出檔案／變更；計畫與驗證回到中央對話，保留可讀性。沿用中文系統字型，不依賴遠端字體。

桌面左側約 224 px，對話可讀宽約 720–800 px；工具展開時分配獨立空間。窄桌面工具改為切換檢視，避免把 Diff 擠成細條。手機收起側欄，任務工具全寬顯示並有清楚返回；任務切換用清單／橫向緊湊列，不平鋪完整桌面。

支援明暗主題、鍵盤焦點、具名按鈕、原生對話框、Escape、觸控目標及 reduced motion。狀態同時用文字表示。主區不水平溢出；程式碼有獨立捲動。

設計研究：ui-ux-pro-max 首次產生的 landing-page pattern 不適合本產品，未採用；以 explicit style query 驗證 Minimalism & Swiss Style 適合專業工具，僅採清楚層級與留白原則。保留現有 `design-system/apsis/MASTER.md`，不將歷史實作規範或資料庫模板整份覆蓋為新需求。
