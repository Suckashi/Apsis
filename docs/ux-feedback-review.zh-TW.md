# UX 盤點：讓使用者知道模型正在做什麼

日期：2026-09-25。範圍：Bot 名單、對話、訊息與附件、模型執行、工具操作、Bot 協作、核准、任務紀錄、供應商與其他設定。

## 本次盤點與調整

| 情境                 | 原本的體驗                                              | 調整後                                                                                  |
| -------------------- | ------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 載入對話             | 只有一行載入文字                                        | 顯示載入指示與骨架，對話尚未載入時停用傳送與附件按鈕                                    |
| 送出訊息             | 按鈕停用，但有輸入內容時看不到 placeholder 的「傳送中」 | 立即顯示傳送狀態與旋轉指示，收到回應後顯示送達確認；失敗保留內容                        |
| 上傳附件             | 和傳送共用 busy，無法辨識正在處理哪個檔案               | 顯示目前檔名與第幾個附件，完成後提示可以傳送                                            |
| 等待第一個模型事件   | 只有概括的工作狀態                                      | 準備任務與等待模型有明確文字，取得執行紀錄後接上進度列                                  |
| 工具執行             | 已有工具名稱與過程紀錄，但所有狀態使用相同脈衝          | 後端提供狀態種類，介面區分執行、等待、回覆與協作；名稱與操作紀錄繼續使用真實事件        |
| 等待核准             | 進度仍像正在執行                                        | 使用靜態暫停圖示、需要處理的文字與提示，保留「前往核准」入口                            |
| Bot 協作             | 有協作名稱與統計                                        | 另外標示協作或等待協作開始，核准狀態優先於執行動畫                                      |
| 長時間没有新事件     | 一直顯示相同狀態，使用者難以判斷是否卡住                | 30 秒未更新時顯示「暫未收到新進度」、距上次進度時間與等待／停止選項說明；不自行判定失敗 |
| 斷線                 | 只有執行中的任務才會顯示斷線                            | 全域即時連線提示常駐；任務區標示狀態可能過期；SSE 重連後重新取得狀態                    |
| 排隊與停止           | 排隊藏在訊息裡，停止按下後沒有專屬狀態                  | 輸入區上方顯示排隊數；停止送出期間有說明且避免重複點擊                                  |
| 結束任務             | 進度列消失，需回到訊息查找結果                          | 輸入區保留最近一次完成、失敗、中斷或取消摘要，以及查看結果入口                          |
| 往上閱讀             | 新內容不打斷閱讀，但回到底部不方便                      | 保留原位置並顯示「回到最新訊息」                                                        |
| 模型供應商／其他設定 | 多數動作已有 disabled、儲存中文字與結果通知             | 補上處理中的可見文字及動畫，模型探索有獨立提示；沿用原有結果與錯誤訊息                  |
| 操作紀錄尚未產生     | 執行中也說「這次任務沒有工具操作」                      | 改成「尚未收到工具操作」，避免把未完成狀態說成最終結果                                  |

## 回饋與動畫規則

- 正在執行使用旋轉指示；等待模型使用較慢旋轉；回覆使用柔和脈衝。
- 等待核准、排隊、失敗與斷線有靜態圖示和文字，不以運作動畫表示持續進展。
- 狀態文字、操作列、核准卡及成功確認用短暫淡入，按鈕有按下回饋。
- 動畫只改 transform／opacity，不推動版面；沒有新增動畫套件。
- 所有裝飾圖示對輔助工具隱藏；重要狀態使用可讀文字及 `role="status"`。每秒計時不放在 live region，避免持續朗讀。
- 遵守 `prefers-reduced-motion`，停用動畫後仍可辨識所有狀態。
- 手機縮減進度區留白；短橫向畫面隱藏輔助說明，保留主要狀態與控制。

## 資訊的真實性

狀態來自模型公開的進度事件、工具開始／結束、Bot 任務與核准資料。介面不顯示模型內部推理，也不憑等待時間編造正在搜尋或整理資料。

30 秒提示代表「沒有收到新的進度事件」，不代表斷線或模型失敗；連線是否正常以 SSE 事件判定。尚未提供總工作量的任務不顯示完成百分比或預估剩餘時間。

設定和草稿、核准、排程等原有表單的錯誤與防重複機制繼續沿用。瀏覽器接管與下載結果仍使用原有入口，本次沒有更動執行權限或對外傳送行為。

## 驗證

- `npm run check` / `npm run build`：TypeScript 與前端打包。
- `npm test`：104 項測試，包括核准優先序、協作等待及回覆狀態。
- `npm run test:bots:browser`：使用本機固定模型回應及隔離資料，驗證送出中的可見回饋、長等待、完成摘要、離線／重連、排隊／停止／取消、閱讀位置、核准、協作、附件與設定。
- `npm run test:settings:browser`：設定儲存、衝突、未儲存編輯保護、中英文、深淺色及手機介面均通過。
- 同一套瀏覽器流程包含 375／768／1024／1440px、橫向畫面、200% 字體、深淺色、鍵盤及減少動畫模式。
- 視覺截圖位於 `artifacts/bot-verification/`，包括 `desktop-progress-quiet.png`、`mobile-progress.png`、`mobile-reconnecting.png`。

模型回應使用測試 fixture；不把這些驗證視為外部模型服務的穩定性保證。
