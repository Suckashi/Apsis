## 調整前的問題

`public/bot.tsx` 的 Bot 右欄仍含自訂 Bot、工作資料、檔案與成果、電腦、排程、記憶、最近操作。`public/coding-workspace.tsx` 又提供變更／檔案／Git／計畫／驗證五個平行入口。兩套內容分工不一致，右欄成為各種管理功能的集合。

重點是每區責任單一、依使用情境展開。單純再把這些區塊折疊，仍保留理解負擔。

## 已實作的分工

- 左：Bots、未讀／待確認狀態、任務／專案導航。
- 中：對話、任務進度、Plan 確認、核准、成果、可展開的命令及驗證紀錄。
- 右：工作內容檢視，主要入口只有「檔案」「變更」。點檔案／Diff／計畫文件時打開對應內容，沒有一排永遠常駐的管理面板。
- Bot 個人設定／頭像 → 點 Bot 名稱或頭像。
- 排程 → Bot 的「⋯」入口。
- 專案知識／記憶 → 專案設定；新增確認留在對話。
- Git 圖與完整提交紀錄 → 變更中的次級入口；分支切換保持任務標題的小型控制。
- Plan → 輸入區模式與對話計畫卡；需要編輯時以文件打開，不常駐一個「計畫」分類。
- 驗證與最近操作 → 對話工具紀錄；不另設同一份資料的右欄分類。
- 電腦預覽 → 移除常駐卡片，沿用已確認的外部瀏覽器操作方向。
- 手機以對話優先，檔案／變更打開成全寬可返回檢視。

此修正保留多 Bot、頭像、平行任務、工作位置隔離和所需功能；重新分配入口，不將「簡化右欄」誤解成刪除系統。

## 實作與驗證

Bot 主對話及任務頁均只保留「檔案｜變更」。Bot 設定改為獨立對話框，排程及舊任務記憶／歷史搜尋移至 Bot「⋯」；引用歷史後返回輸入框。專案頁提供專案說明與分範圍記憶設定，更新／合併不能越過專案，舊版本寫入回傳 409。Plan 卡位於任務對話中，編輯時才打開文件；Git 圖收在變更內，驗證紀錄在對話中展開。移除常駐電腦預覽及重複的頂部 Plan 入口。

型別檢查、build、218 項單元／整合測試及六套桌面／手機瀏覽器流程通過。實際模型與遠端 PR 整條流程的既有限制仍見 `coding-workbench.md`。
