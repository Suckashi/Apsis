# Apsis 整體品質驗收基準

更新：2026-10-01。範圍維持使用者要求的完整產品品質目標，目前實作與驗收優先桌面。這是產品的內部驗收基準，不是獎項評審分數，也不把功能測試通過當成獲獎證明。

## 官方依據與界線

[Awwwards 官方 Evaluation System](https://www.awwwards.com/about-evaluation/)本輪經使用者 Chrome 實際讀取，確認設計 40%、易用性 30%、創意 20%、內容 10%。官方頁說明 SOTD 由評審選出最高分作品；因此不能以自訂總分或通過率推論獲獎。本輪僅確認此評估頁，沒有完成 Developer Award 全部指引的驗收。

[Webby 官方 2026/2027 Judging Criteria](https://www.webbyawards.com/judging-criteria/)分別列出網站及 Apps、Software & Immersive 面向，涵蓋內容、導覽、視覺、功能、互動、創新及整體體驗；軟體面向另涉及執行與品牌。Apsis 應以使用者是否能順利完成工作及持續使用來檢查整體體驗，不能只看首頁外觀或局部自動掃描。

[FWA 官方 About](https://thefwa.com/about/about-fwa/)本輪經 Chrome 實際讀取，確認其重點在數位創新、創意及向前推進的作品，且涵蓋網站與應用。該頁沒有給出完整數值評分規則；本文件不沿用第三方網站宣稱的權重，不宣稱已取得 FWA 的全部評選要求。

## 接續優先順序

1. 解決第七十輪回報內容的真實缺口。已確認 executionContext 有送進模型，目前沒有證據支持「指令遺漏」這個根因；不可再把增加提示字串本身當作改善成功。
2. 完整審視桌面主要狀態的品牌與視覺，將局部變更統整成同一套呈現，保留手機暫緩的使用者決定。
3. 補足實際長任務、複雜文件、人工可及性與裝置效能的缺口，依真實結果修正。
4. 最終逐項對照上述要求及 [品質紀錄](product-quality-audit.md) 的剩餘工作。缺少證據、觀察不一致或仍有未完成項時，目標保持進行；不給自行估算的獲獎分數。
