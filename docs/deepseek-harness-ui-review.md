# DeepSeek Harness 對照與 Apsis 介面收斂

2026-10-01。依使用者要求，實際查看 Chrome 中的 DeepSeek Harness（127.0.0.1:3080）和 Apsis（localhost:3100），並完成第一輪介面調整。

## 觀察

2026-10-01 後續多檔實測：同一離線待辦清單需求，Harness 三檔交付且清楚承認只查原始碼；側欄版面有載入，但實際新增沒有改變列表，原因未定位。Apsis 首次被開發服務重啟中斷；改善監看與補 reload 驗證後，接續任務實際通過 18 步驟／11 斷言，三檔一次發布，使用者 Chrome 預覽新增／完成可操作，真實 ZIP 下載內容符合驗證來源。兩邊模型不同，不以耗時比較速度。細節與未驗證限制見品質自我檢查第六十輪及 artifacts/live-multifile-comparison/。

Harness 的左側依工作區找對話，中央保留閱讀空間，模型和權限放在輸入區；執行細節可展開，右側工作面板預設收起。值得借用的是清楚的資訊層級。

Apsis 已經有聊天主畫面，但常用的模型、核准與工作位置藏在 Bot 選單的聊天選項，歷史瀏覽又混在記憶管理中。桌面同時有兩個名單收合控制，專注模式也占用頂部常駐位置。

Apsis 保留「先選 Bot，再處理專案工作」的產品方向。Bot 身分、頭像和長期合作關係仍是主要入口；沒有把 Bot 改成 Harness 的一次性 Session。

## 第十二輪：文件任務與可讀的工作計畫

文件副檔名存在仍不足以代表交付成功。Apsis 已發布 DOCX 快照只有純段落、沒有標題樣式；PDF 實際渲染為兩頁、缺少標題與正文的區別。DOCX 尚未渲染；本輪瀏覽器下載 helper 逾時後失去分頁控制，本機快照檢查沒有冒充下載驗證。新生成的內容可讀，但約一頁與層級排版仍未達要求，後續優先改進原生文件工具。

Apsis 工作計畫保留按需展開，收合即可看見真實完成數與當前步驟，展開項目有明確文字狀態。根計畫更新保留展開、子代理不覆蓋、結束不自動補成 100%；說明計畫完成不等於成果已驗證。沒有新增常駐百分比或數據面板。另修正英文短橫向畫面的頂列擠壓與零高度對話，移除進行中文字的掃光，使長任務閱讀更穩定。
