# Apsis Bot 工作空間

`npm run dev` 啟動 Apsis Bot 工作空間。Bot 統一使用 Deep Agents 搭配第三方 LLM API／Ollama。Deep Agents 原生 `task`、`execute` 已停用，派工與主機工具均由 Apsis 管理。

## 啟動

需要 Node.js 22.19 以上。

```sh
npm ci
npm run dev
```

開啟 http://localhost:3100。到「設定與工具 → 模型連線」新增 OpenAI 相容 API、OpenAI、Anthropic 或 Ollama，填入模型 ID，設為預設。使用「測試」確認供應商的串流和工具呼叫。API key 儲存在本機，不回傳到前端。

Codex／ChatGPT 登入執行路徑已退役。既有 Codex Bot（包含沿用舊預設連線者）保留歷史與檔案，會提示重新選擇模型，其排程也會停用。選擇支援的明確模型或全域預設後才能執行，排程需另行重新啟用；不會自動轉往付費 API，也不會重播錯過的工作。這不會解除安裝 Codex 或刪除本機登入憑證。

本機 Ollama 可填入 `http://127.0.0.1:11434` 和已安裝的模型 ID（例如 `qwen3.5:9b`）。同一模型也可用「OpenAI 相容」服務測試，Base URL 改為 `http://127.0.0.1:11434/v1`；此本機端點不需 API key。這是兩條獨立連線，設定其中一條為預設即可。

瀏覽器工具優先使用 Playwright 的 Chromium；Windows 未安裝時會尋找已安裝的 Chrome／Edge，使用 Apsis 專屬資料夾，不使用你的日常瀏覽器設定。其他環境請先執行：

```sh
npx playwright install chromium
```

也可以設定 `APSIS_BROWSER_PATH` 指向瀏覽器執行檔。

## 主要操作

1. **選 Bot 聊天**：每位 Bot 有角色、模型與記憶。傳訊息直接交辦，程式工作也留在同一條聊天。
2. **補充與停止**：執行中直接傳訊息補充；已收到、已採用、未採用明確區分。未採用可以重新傳送，停止不會撤銷已完成的外部操作。
3. **看進度與成果**：聊天顯示目前進度與最後結果；工具紀錄和派工細節可展開，成果可預覽或下載。
4. **新話題與聊天選項**：Bot 選單提供開啟新話題、模型、核准模式和工作資料夾。新話題切開模型背景，舊訊息仍可搜尋與查看。
5. **檔案、修改與排程**：檔案和 Git 修改按需開啟側面板；排程、記憶與 Bot 設定由 Bot 選單進入。手機使用抽屜／全畫面檢視。
6. **技能與連接器**：共用資料夾技能自動提供給所有 Bot；Bot 設定保留 MCP 連接器選擇。輸入框的工具選單可加附件或插入連接器引用。

在「自訂 Bot」表單下方按「刪除 Bot」並確認，會停止任務，移除對話、專屬記憶與技能、排程、草稿、核准規則及附件／成果清單，並關閉該 Bot 的瀏覽器分頁。工作區實體檔案、執行日誌與既有備份保留；外部操作不會撤銷。刪除無法從介面復原，外部草稿正在傳送時需等待完成後重試。

## 頭像收藏

所有 Bot 共用點數與收藏。沿用原本四十八款頭像、配色與系列：六款基本款免費使用，另有八個收藏系列。選擇時可查看大預覽，並依系列與已擁有狀態篩選；系列篩選僅影響顯示，不影響抽池。頭像識別碼保留，既有 Bot、範本、收藏、點數與抽取紀錄沿用，不需要重新抽取。

點數只有一條規則：成功完成一次主要工作（包含聊天與排程）得 10 點，30 點抽一位新夥伴。協作子任務不另計點，失敗、取消、中斷的工作不發點；舊工作不補算，同一份完成紀錄只計一次。原本的首次協作、排程及交付加點已停止發放，既有獎勵與點數仍保留。

在新增／自訂 Bot 或範本編輯的頭像區，花 30 點抽一款尚未擁有的新頭像，每款等機率、保證不重複。抽到後可選用，再儲存變更；不會自動替換 Bot 頭像。點數規則、已擁有款式、剩餘抽池與最近一次結果都可在此查看。網路中斷時按「確認上次抽取結果」，沿用原請求，不會重複扣點。集滿後停止抽取，但繼續累積點數。刪除 Bot、重新整理或重新啟動不會清除收藏。

## 設定、範本與語言

執行設定包含步驟數、有效執行時間、Shell 秒數、證據輸出字元數、派工深度、工作數與同時執行名額。預設分別為 100、30 分鐘、60 秒、24,000 字元、3 層、12 個工作及每個根任務 4 個名額。每次執行取得限制快照，子任務沿用；等待核准或子任務時會釋放執行名額。設定儲存會檢查修訂版本，遇到衝突需重新載入再套用修改。

Bot 範本可保存角色、圖示、模型、技能與連接器選擇及權限，建立新 Bot 時複製設定。範本不包含憑證、對話、記憶或執行狀態；編輯或移除範本不影響既有 Bot。失效的模型參照需先更換。

語言偏好可保存為繁體中文（`zh-Hant`）或 English（`en`），用於已本地化的介面文字。訊息、工具證據與使用者內容不會自動翻譯；目前不宣稱完整介面翻譯覆蓋。API、限制與遷移細節見 [設定平台](settings-platform.md)。

## Bot 協作與秘書派工

每位 Bot 都可用 `list_bots` 查看其他未隱藏 Bot 的名稱與角色，再用 `delegate_task` 交辦工作或詢問問題。接收方沿用自己的模型與角色，在自己的對話中執行；忙碌時先排隊，完成後將該任務的結果與成果清單交回派工方。秘書會在原對話繼續整理回覆。

例如，建立「秘書」「研究員」「文案」三位 Bot，在秘書的角色寫入「依其他 Bot 的專長分工，收到結果後整理給我」，然後交辦：「請研究員整理這份資料，再請文案依研究結果寫一段介紹，最後由你彙整。」任務中需明確提供必要背景或工作區檔案路徑。派工工具本身只回傳該任務結果，不讀取接收方的整段歷史或私有記憶。

執行中，輸入框上方會顯示目前動作、總耗時與協作進度；沒有具體事件時會顯示「等待模型回應」。需要工具核准時，可按「前往核准」切換到接收方對話。公開工具事件會即時更新，不顯示內部推理。

每次回答下方會保留一行任務摘要，點開可查看操作與 Bot 協作。紀錄先顯示最近 10 筆，可逐次展開更早紀錄；每筆再展開才顯示完整任務、結果與「開啟 Bot 對話」。已主動展開的任務在完成後保持開啟。失敗、中斷、取消與結果不明會明確標示；無法對應至某次任務的舊協作，保留於「較早協作紀錄」。

停止秘書會取消其正在等待的派工，不會停止接收方正在處理的其他任務。互相等待的循環派工會被拒絕；預設每個根任務最多派出 12 個工作、最多 3 層轉派，可在執行設定調整。接收方必須同時符合所有上游 Bot 的限制；派工中建立的排程及後續子任務也會保留這些限制。服務重啟後未完成的工作標為中斷，不自動重播。

## 任務工作資料夾

每位 Bot 保留持續主對話；「開啟新話題」切開背景與記憶範圍，預設工作資料夾在第一次寫檔時建立。右側「檔案」只提供目前任務的檔案樹與唯讀預覽、下載及引用；聊天選項中的工作資料夾入口可連結既有位置。檔案修改直接交辦 Bot，專案管理不出現在檔案面板。派工、排程與重試固定使用來源位置，成果保持獨立快照。完整行為、API 與遷移方式見 [任務工作資料夾](task-workspaces.md)。

## 工具、附件和成果

- 新話題的預設位置：`.apsis/workspace/tasks/<id>/`；也可連結既有資料夾或專案。可列檔、讀取、精準修改、寫入及使用本機 Bash（Windows 使用 Git Bash）。
- 工具核准預設採 Kimi 式「需要時詢問」（yolo）：一般操作直接執行，命中危險或敏感路徑等前置策略才詢問；也可選擇 manual 或 auto。唯讀與禁止規則仍優先，詳見 [核准模式](approval-modes.md)。
- 唯讀模式拒絕資料修改、Shell、MCP 呼叫與瀏覽器修改操作，允許規則不能覆蓋。路徑規則按目錄邊界比對，Windows 不區分大小寫；不接受絕對路徑、跳出工作區或模糊路徑別名。
- 核准可只允許一次，或允許本次任務內相同操作，包含向下派工。此授權先於一般詢問規則，但不能略過危險命令；新話題不繼承。舊版永久核准留作不生效的歷史紀錄。
- Shell 在主機執行，工作區不是作業系統沙箱，路徑規則不能限制命令內部存取的檔案。需要僅限檔案工具的 Bot 應拒絕 Shell。Shell 預設 60 秒、設定上限 120 秒；任務預設 100 個步驟／30 分鐘有效執行時間，等待核准不計入時間。
- 支援上傳 TXT、MD、CSV、PDF、DOCX、XLSX、PNG、JPEG，每個檔案最多 20 MB。PDF 讀取文字層，沒有 OCR；圖片需要模型支援視覺。
- 可讀取文件，產生 DOCX、XLSX、PDF，或發布已寫入的程式碼／Markdown 等檔案。成果保存獨立快照，後續修改原始檔不影響已發布成果。
- MCP 支援 **Streamable HTTP + 選用 Bearer token**。連接器透過 `.apsis/mcp.json` 管理，設定頁入口已隱藏。Bot 可準備操作草稿，由使用者修改 JSON 參數後傳送或捨棄；傳送前會重新檢查連接器選擇、唯讀與上游拒絕規則。傳送結果不明時不自動重試。
- 瀏覽器共用持久登入狀態，每位 Bot 有自己的分頁。先停止執行中的任務，再按「接管瀏覽器」，開啟本機專用視窗；交還後恢復自動操作。接管切換會重新載入分頁，網頁未提交的暫存內容可能不保留。

## 排程

可從聊天請 Bot 建立排程，或在詳情手動設定名稱、內容、Cron 與 IANA 時區。支援暫停、修改、立即試跑與執行紀錄。Apsis 需持續執行；錯過多次排程時補執行一次，避免重複批量操作。

## 資料與恢復

- 所有執行資料放在 `.apsis/`。
- Bot、佇列、設定版本、範本、權限、核准、草稿、排程、成果索引及事件使用 SQLite（WAL）；對話與知識沿用經驗證的原子 JSON 儲存，執行日誌另外保存。憑證僅存在本機資料目錄。
- 瀏覽器重新整理透過 SSE 重新訂閱並讀取最新狀態，不會中止伺服器任務。
- 服務重啟後，執行中／排隊中的工作標為中斷，核准過期，傳送中的草稿標為結果待確認；不自動重播可能有副作用的操作。

## 驗證

```sh
npm run build
npm test
npm run test:bots:browser
node scripts/verify-settings.ts
```

瀏覽器整合測試使用隔離資料目錄及可重現的模型替身；實際操作頁面、瀏覽器、檔案、Shell 核准、下載、排程、PDF 和手機版。截圖存入 `artifacts/bot-verification/`。第三方模型的真實帳號仍需用自己的連線測試確認。

設定專用驗證腳本 `scripts/verify-settings.ts` 需在 build 後執行，使用本機替身檢查設定介面，報告與截圖存入 `artifacts/settings-verification/`。測試範圍不等同完整翻譯覆蓋，結果以該次產生的報告為準。

啟動本機 Ollama 後，可執行 `npm run test:bots:ollama`，以隔離資料實測秘書尋找另一位 Bot、派工並取得結果。預設使用 `qwen3.5:9b`；可用 `OLLAMA_MODEL`、`OLLAMA_URL` 調整。此測試會實際呼叫模型，確認子任務確實完成，並非只檢查回覆文字宣稱已派工。

介面提供繁體中文／英文語言偏好與淺色／深色模式；外觀可從側邊欄下方切換並記住選擇。手機版使用側邊抽屜；設定與排程視窗支援鍵盤焦點切換及 Escape 關閉。尚未包含原生桌面操作、語音、多使用者及 MCP OAuth／stdio。
