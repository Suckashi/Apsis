6. 確認沒有 active job 後，改成相同 3100 埠的非 watch 服務，再透過產品輸入框續作。Cloudflare gateway／tunnel 設定未更動。

## 本輪已修正的 Apsis 問題

- 長 shell 命令改由 stdin 完整讀取再執行，避免 Windows argv 靜默截斷；腳本執行前已讀完來源，維持子命令 stdin EOF，處理 EPIPE 並保留退出碼、逾時與取消。
- `invalid-path` 回傳可操作的相對路徑提示；工具授權拒絕也記為持久化 failed operation，避免重複紀錄。
- 建立 coding task 後立即開啟回傳的任務。
- 保存任務頁籤與選取狀態，取得有效 snapshot 後驗證 ID；失效 ID 不會發出錯誤任務請求。
- snapshot 提供精確 `chatRunning`，不再把 coding task 同時計入對話執行數。
- 最後補明 coding 系統提示的發布範圍：push／PR／遠端發布須有此任務的明確授權，本地需求完成本地驗證後回報並停止。舊提示不是字面強制 push，但無條件介紹 PR workflow，缺少範圍條件；這是可能的誤導來源，不能斷言是模型偏離的唯一原因。

修正驗證：`npm run check`、build、全部 246 項 Node 測試通過；coding-workspace 瀏覽器回歸通過，包含建立即開啟、單一任務計數、F5 與兩邊草稿保留、過期 ID，以及計畫／diff 流程。另在實際服務中重新整理確認同一任務與草稿保留、執行中顯示 1（[截圖](../artifacts/live-ux-20260929/screenshots/11-restored-task-draft.png)）。

發布提示另有新增 3 項 contract 測試通過，最後再次 build 成功並重啟到同一 3100 埠（HTTP 200），服務保持運行。這項提示調整尚未再發真實模型請求驗證，也沒有宣稱它等同不可繞過的發布權限控制。

其餘表格項目仍是待改進項目，並未因這批窄修而全部完成。原本的模型連線可以正常發出與接收真實請求，但本次首次端到端實作未能在零介入下完成。

### 真實請求用量的解讀

規劃階段 4 次請求累計 input 39,796／output 1,645 tokens；首個請求 input 9,839。第一次實作在中斷前已保存的 15 次模型回覆累計 input 294,116／output 25,586；第一個請求 input 11,471／output 3,359，其中 reasoning 3,194。這些 input 是多次請求的累計，包含重複上下文及快取輸入，不代表單次 context 大小，也不能直接當作實際帳單金額。

被重啟中斷的 run API usage 為 null，但 archive 已有上述用量；null 不能被當成「沒有消耗 token」。首次 49 秒等待無法僅憑這些數據歸因給 provider 網路或上下文大小。

穩定服務上、修復 harness 前的第二次實作（後由使用者介面停止）已有 15 次保存的模型回覆，累計 input 712,643／output 20,065；input 其中 cache-read 657,670，output 其中 reasoning 5,310。首個 request input 38,376、末個 54,889。這呈現了反覆重試對上下文與用量的影響；未保存的回應與請求不能由這份紀錄補算。

最終共 6 個 run：1 個規劃 completed、2 個重啟 interrupted、3 個由實測者 cancelled，沒有仍在執行的工作。保存的模型回覆共 95 次，累計 input **5,804,398**／output **73,672**；input 包含 **5,534,638 快取輸入（95.35%）**。不是單次 580 萬 context，也不是等價的全價 token 成本；單次 input 從 9,839 增到最後 95,098。6 個 run 實際執行時間合計約 **17 分 34 秒**，不含暫停修 harness、人工操作與等待的牆鐘時間。

### 接下來的驗收順序

1. **交付要有端到端證據**：在瀏覽器對最終版本驗證正常、錯誤、重設、鍵盤及追加需求。將單元測試與 UI 驗證分開顯示。
2. **工作範圍可控**：本地需求不 push／建 PR；失敗重試有可見的障礙與有效的中途修正入口。
3. **工作區真正獨立**：避免從 Apsis 宿主繼承 package、編譯器與執行設定。
4. **中斷可恢復**：補充留在原任務並顯示是否採用，明確重試且不重複執行。
5. **精簡工作畫面**：建立 Bot 基本欄位優先、短標題、最新計畫只保留一個入口、手機縮短固定標頭；動畫只用於清楚表示真實的狀態轉換。
